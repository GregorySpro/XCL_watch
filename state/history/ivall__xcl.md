# Historique : ivall/xcl

## État du projet

Après ce commit, le projet compile toujours, les 130 + tests restent verts et le test de scalabilité reste valide. Le code de sparse planning conserve la logique de revalidation bornée, mais elle n’est plus sélectionnable, ce qui simplifie le chemin d’exécution sans introduire de régression connue. Les blocages précédents (fuzz‑tests, support de pilotes alternatifs, optimisation compute, validation sur titres réels) demeurent, et la prochaine étape probable reste l’exécution de smoke‑tests retail sur Windows ainsi que l’évaluation des performances du fast‑path sparse.

Cette modification s’inscrit dans la continuité du chantier d’optimisation du cache des pipelines compute, en éliminant les variations dues à des pointeurs nuls ou du padding qui ne participaient à aucun état actif. Désormais les flux vides ou les shaders optionnels vides n’altèrent plus la clé, ce qui améliore la stabilité du cache ; les états actifs non supportés continuent de provoquer un rejet comme avant.
